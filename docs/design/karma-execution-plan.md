# Karma Quest モック再現・実行手順

## 目的と優先順位

正式モックの構図・人物の存在感・UIの質感を再現し、スマホで読みやすく操作できる4画面を完成させる。現在の実装状況は末尾と最新レビューを参照。テスト成功だけを見た目の合格判定に使わない。

基準画像は [写真5](../review/karma-visual-mock.jpg)。ユーザーの指定（素材を伸ばさない、文字を読みやすく、UIを重ねない、依頼画面は背面人物を使わず左下バストアップ、指定ボタンを基準にする）を最優先にする。次に正式モック、[UI基準](karma-ui-design-system.md)、[画面設計図](karma-screen-blueprints.md)の順で参照する。既存座標は実装メモであり、モックに近づけるため修正してよい。

今回の進行順は本書を優先する。他5作品、新機能、無関係な共通化は対象外。まず王都ホームの縦画面を仕上げ、残りの縦3画面、横画面の順に進む。ユーザーへの再確認を各段階の必須条件にしない。

## 実行ループ

1. `git status --short` と適用対象の `AGENTS.md` を確認し、他の変更を保護する。
2. 正式モックの対象画面と現在の実画面を読む。資料の見出し・外枠はゲーム画面の比較に含めない。
3. 同じ画面幅で比較し、差を「構図、素材、UI寸法、文字、装飾」に分類する。最も目立つ未解決項目を3件以内で記録する。
4. 構図 → 素材 → UI寸法 → 文字 → 装飾の順に修正する。必要な素材が既存素材で作れない場合はimagegenスキルに従い制作し、出典・用途・寸法を素材台帳へ記録する。
5. スクリーンショットを撮り直して目視する。文字や顔を隠す、素材を歪める、別の領域を押し出す変更は戻すか修正する。
6. 以下の合格条件を満たすまで同じ画面で反復する。小さな修正やコミットを理由に作業を終了しない。
7. 合格した画面から部品を共通化して次へ進む。変更による回帰を確認し、設計図と画像を実装に同期する。

## 作業順と成果物

| 順序 | 作業 | 合格条件・成果物 |
| --- | --- | --- |
| 1 | 王都ホームの比較基準を作る | 同幅のモック・現状比較画像と差分リスト。背景、人物、見出し、依頼カード、ナビの占有領域を明記 |
| 2 | 王都ホームを仕上げる | 背景の見える範囲、人物の大きさ・位置、主文の位置がモックに近い。HUD・ナビ・依頼カードが読みやすく、画面内で分離 |
| 3 | 選択シーンへ展開する | 左下バストアップ、依頼者、本文、青赤CTAを独立した領域に配置。依頼内容に合ったボタン文言と説明。長文でも縮小・重複なし |
| 4 | 世界の反応へ展開する | 場面絵、結果、住民の反応、変化一覧、次へが順に読める。承諾・拒否と依頼内容に表示が一致。結果表示中の裏側の進行・入力も検査 |
| 5 | 年代記・成長へ展開する | 出来事、未解放、街、主人公、操作をモックの順で配置。主人公は顔が読める大きさ。記録・成長値は実データと一致 |
| 6 | 横画面を設計・実装する | 縦画面の単純縮小を避け、場面絵と情報面を左右へ配置。4画面に加え、その間の遭遇・戦闘・報告も切れずに操作可能 |
| 7 | 通し検証・提出 | 全画面比較、スマホ画像、検証結果、残件をまとめる。差分確認後にcommit・pushして既存PRを更新 |

## 見た目の合格条件

- 背景、人物、主見出し、主要カード、主要操作の位置と大きさを比較画像で評価する。大きな構図の差を装飾追加でごまかさない。
- 顔と本文、別々の情報カード、操作領域が互いに重ならない。人物にカードが重なる演出は胴体・裾の範囲だけとし、顔・手など重要部分を隠さない。
- 素材の拡縮は縦横同率。トリミングは顔や重要な持ち物を欠損させない。画面全体を1枚のモック画像で代用しない。
- 320px幅の実表示で本文は原則14 CSS px以上、補足は12 CSS px以上を目指す。主要CTAは52 CSS px以上、その他の操作は44 CSS px以上。設計pxとCSS pxを混同しない。
- 読めない長文は本文領域・改行・情報配置を調整する。必要な情報を黙って省略したり文字だけを縮めたりしない。
- 金枠、羊皮紙、紺・赤の操作面、文字階層が4画面で統一されている。各画面を並べても装飾密度に不自然な差がない。
- 合格判定には「モックとの差」「修正内容」「残った差」を記録する。根拠のない再現率や、テスト件数だけの完成判定はしない。

## 動作・検証手順

実行場所: `games/karma-quest`。

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run e2e
```

各コマンドの終了コードを個別に確認する。失敗後に後続コマンドが成功しても、全成功とは扱わない。テスト対象設定に追加テストが含まれることを確認する。

縦の確認サイズ: 320×568、360×640、375×667、390×844、430×932。横: 800×360、844×390、932×430。タブレット: 768×1024、1024×768。Safe Areaと画面回転を含め、画像比率・可読性・領域の収まり・タップ位置を検証する。

通常・最長文・承諾・拒否・連打・押下後に外へ移動・画面回転・次画面からの再操作を検査する。スクリーンショット用の固定データだけでなく、通常起動から実際の一連の遷移も確認する。

回帰画像は実装の確認用であり、正式モックそのものではない。新画像を目視してから意図した画面だけベースラインを更新する。画像の自動更新で差を消しただけでは合格にしない。実機で未確認のノッチ・ブラウザバー・音・長時間動作は、エミュレーションと分けて報告する。

## 停止・報告

通常の実装判断、素材調整、検証、commit・pushは既存の依頼範囲で進める。モックとユーザー指定が両立しない場合は指定を優先し、変更理由を記録する。作業中は発見・修正・次の確認を簡潔に報告する。

ユーザーの停止指示、必要情報や外部環境による解消不能な障害、または上記の完了条件達成時に終了する。未完成のまま終了が必要になった場合は完成と表現せず、未解決項目と再開箇所を残す。PRのマージ・本番公開はこの手順の完了条件に含めない。
